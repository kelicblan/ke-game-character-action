# 自动化执行协议 V2.0

## 定位与边界

`ke-game-character-action` 是一个独立 Skill，不引用任何其他静态角色 Skill。V2 以 **真实角色图片 + 角色动作方案 JSON** 为输入，调用当前宿主提供的图片工具，生产真正的精灵序列和图集。Python 本身不包含图像生成模型；宿主 AI 按 `next/ingest/review` 调用当前图片工具，或用 `run --generator` 连接用户本机可执行生成器。不存在工具就报告阻塞，不冒充生成成功。

## 执行步骤与状态机

1. 宿主 AI 阅读真实原图，分析结构、关节、质量感、步态、受击部位和方向，按 `templates/action_plan_v2.example.json` 输出 version=2.0 的动作卡。
2. `init` 创建外部 job 目录，复制原图，锁定 SHA-256，并保存每帧的 pending 状态。
3. `next` 返回按状态及顺序生成的下一帧：生成 Prompt、当前帧阶段、原图引用、同动作前一帧/前一状态锚点、上次失败原因。
4. 真正调用宿主图片模型。结果须是实际存在的图片文件；`ingest` 导入单张 RGBA 图，或使用 `ingest-grid` 切开真正均匀格子的帧图。可显式配置绿色或洋红色键，输出必须是真实透明 PNG。
5. 结构 QA 校验 Alpha、非空轮廓、帧尺寸和文件摘要。失败自动拒绝并记录。
6. 图片生成工具或视觉审查器对每帧、相邻帧进行身份、比例、姿势、受力方向、重心、脚部支撑、进退位置、节奏连续性检查。通过才 `review --pass`；不通过 `--reject --issue ...`，自动将具体问题加入下一轮 Prompt。
7. `run --generator ... --reviewer ...` 可自动执行完整循环；失败默认最多重试 3 次，达到上限报告 blocked，不无限循环。
8. 所有帧通过审查，`build` 将帧居中、脚底对齐，生成 RGBA 图集、每帧 Rect 和 durations_ms、动作事件、原图与帧摘要检查、中文 HTML 预览、Cocos 运行时资源包。

## 严格的质量含义

- `generated` 只意味着**图片结构有效**，并不代表角色/动作正确。
- `accepted` 代表调用方的外部视觉审核器或人工/Agent 实际检查并确认通过。
- `draft` 图集只可预览，不应作为已经完成视觉验收的游戏素材。
- `visually_reviewed` 不等于 Cocos 引擎实际运行通过。
- 程序统计只能检测重复帧、Alpha 和尺寸；不能确定“头部受击是否真的后退一步”，这由视觉审核与玩法测试负责。
- 只提供图集与 Cocos TypeScript 播放组件，不伪造 native `.anim`／Prefab 或已在用户工程中运行的结论。

## 命中与移动规则

根据真实命中部位（头、腹、头顶、侧头、脚等）、受力向量、强度和当前状态（地面、跳跃腾空、漂浮、落地）生成不同动作。动作 JSON 的 `hit_context` 控制视觉生成；真实位移归游戏逻辑根节点所有，不能靠图集重置位置来模拟后退。出招需明确预备、加速、接触、停势、后摇、恢复及事件 `at_ms`。保持真实毫秒时长，不用“每帧相等”代替动作节奏。

## 中文预览与 Cocos 资源

`previews/动作预览.html` 无网络依赖，嵌入图集 Base64，可控制：
全部播放／暂停／重播、正常与慢速播放、各动作上一帧／下一帧／时间轴、动作总时长/帧数及当前审核标志。HTML 在本地浏览器可打开；它不是自动发布的公网地址。

`cocos/` 包含图集、元数据 `JsonAsset` 和 `CharacterActionPlayer.ts`。在 Creator 3.8 工程中导入图片、JSON 和 TS，在 Inspector 上配置 Texture2D、JsonAsset 和 Sprite；使用 `play(state)` 切换动作，监听事件。实际 hitstop、受击硬直、位移、碰撞、死亡锁定由战斗系统实现。

## 可复现测试

`pip install -e .`

`python -m unittest discover -s tests -v`

回归测试使用临时目录与 **仅用于测试的虚构图像生成器**，覆盖动作 JSON 校验、失败帧拒绝、生成、自动拒绝重绘、资源检查、图集及中文网页输出、Cocos 文件生成。测试不调用收费图片模型，不作为真实角色外观或引擎运行的验收证据。

生成素材、历史图片和测试产物始终在外部临时目录，不应提交进 Skill 仓库。
